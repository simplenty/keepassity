# fixture-gen — synthetic KDBX fixture generator

The repository's own (synthetic) KDBX fixtures are generated by Rust code in
[`crates/core/tests/synthetic_fixture.rs`](../../crates/core/tests/synthetic_fixture.rs),
not by a separate tool. This directory only contains the convenience wrapper
that regenerates the file **and** refreshes the SHA-256 manifest entry.

| File | Purpose |
|---|---|
| `regenerate.ps1` | Run the ignored generator test, patch `tests/fixtures/manifest.json`, then run `scripts/verify-fixtures.ps1` |

## Usage

```powershell
# from the repository root
pwsh -File tools/fixture-gen/regenerate.ps1

# only refresh the manifest hash (file already regenerated):
pwsh -File tools/fixture-gen/regenerate.ps1 -SkipGenerate

# share the cargo target directory to avoid a rebuild:
pwsh -File tools/fixture-gen/regenerate.ps1 -CargoTargetDir ..\out\cargo-target
```

The generator draws a fresh KDF salt / master seed / IV, so the file bytes change
on every run and the committed manifest hash must be updated together with the
file. `scripts/verify-fixtures.ps1` is the final gate; it fails if the manifest
and the file disagree, or if an unregistered `.kdbx` appears under
`tests/fixtures/`.

The fixture itself and its entry composition are documented in
[`tests/fixtures/synthetic/README.md`](../../tests/fixtures/synthetic/README.md).
All values are synthetic test data with a public master password (`demopass`);
never add real credentials to a fixture.
