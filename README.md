# keepassity

A Windows-first, open-source password manager for KeePass **KDBX** databases, with native
**WebDAV** support and built-in **TOTP**. Rust core + WinUI 3 shell, GPL-3.0-or-later.

> **Unofficial.** Not affiliated with, endorsed by, or sponsored by the KeePass project.
> "KeePass" is a trademark of its owner; this project only reads and writes `.kdbx` files.

## Status

**v1.0.0 (release pending acceptance).** The Windows app covers the v1.0 scope: it opens
local files or databases served over WebDAV, unlocks, browses, edits, moves and saves entries
and groups, shows and edits TOTP codes (including QR / `otpauth` import and next-window
prefetch), keeps timestamped local backups with restore, and syncs over WebDAV with explicit
three-choice conflict handling. KDBX compatibility is checked against `keepassxc-cli` in CI;
the manual G3/G4 gates (main flows, real Jianguoyun sync, install/uninstall) were signed off
on 2026-11-08/09, and the app has been used against a real KeePass 2.x database (G0,
2026-10-25: round trip, KeePass 2.x reopen, 10-entry spot-check including 3 TOTP codes).

v1.0.0 is **not published yet**: the 1.0.0 build goes through a 30-day real-use acceptance
before the `v1.0.0` tag and GitHub Release are created. No GitHub Release has been published.
The binaries are unsigned (SmartScreen warning), and there is no MSIX packaging or
auto-update. Key file / challenge-response credentials and Windows Hello are out of scope for
v1.0, and there is no attachments/history/recycle-bin management UI (the data itself is
preserved). The v1.0 scope is frozen by the maintainer.

## Features

- **KDBX:** opens KDBX 3.1 / 4.0 / 4.1 databases with a master password; saves go through the
  KDBX 4.0 write backend (see `docs/compatibility.md`), with a timestamped backup before each
  write.
- **WebDAV:** open a `.kdbx` directly from a WebDAV URL (the encrypted file is downloaded to
  a local working copy, unlocked locally, and written back), sync on save and on demand,
  three-way merge of non-overlapping changes, and conflict copies plus a Keep local /
  Keep remote / Keep both choice when the same item changed on both sides.
- **TOTP:** read, display, edit and generate codes for both KeePass `TimeOtp-*` and
  `otpauth`/`otp` fields; import from a QR image, a clipboard QR screenshot or an
  `otpauth://` URI.
- **Backups:** configurable retention (default 20 copies), list and restore from the app.
- **Security:** auto-lock after inactivity and on Windows session lock/logoff/suspend,
  clipboard secrets cleared after 30 seconds and marked not to enter Win+V / cloud clipboard
  history, WebDAV passwords stored with Windows DPAPI.
- **Shell:** English WinUI 3 UI with system/light/dark theme, search, sorting and filtering,
  entry/group drag-and-drop, tray menu (show / lock / exit), single-instance behaviour,
  inline settings panel and `--selftest` mode.
- **Windows integration:** the installer is per-user (no administrator rights), installs
  under `%LOCALAPPDATA%\Programs\keepassity` with Start menu / desktop shortcuts and an
  uninstaller that keeps user data, and registers a per-user candidate `.kdbx` association
  (no default-app override) so a double-click opens keepassity after the user
  confirms/chooses it in Windows.

## Install and run

Release artifacts are built from a `v*` tag by `.github/workflows/release.yml`. Each release
draft contains:

| File | What |
|---|---|
| `keepassity-<version>-win-x64-setup.exe` | Inno Setup installer (per-user, no admin rights) |
| `keepassity-<version>-win-x64.zip` | portable build (self-contained, no .NET runtime needed) |
| `SHA256SUMS` | SHA-256 of every released binary |
| `sbom.spdx.json` | SPDX software bill of materials |

Build provenance attestations for the artifacts are generated by the same workflow
(`actions/attest-build-provenance`).

No GitHub Release has been published yet. The current build is `v1.0.0`, which goes through a
30-day real-use acceptance before the tag and release are created. Until then, build the
portable folder from source (below).

Once a release is published:

1. **Verify the download.** Compare the file hash with `SHA256SUMS`:

   ```powershell
   Get-FileHash .\keepassity-1.0.0-win-x64.zip -Algorithm SHA256
   # compare with the matching line in SHA256SUMS
   ```

   With the GitHub CLI you can also check the build provenance:

   ```powershell
   gh attestation verify .\keepassity-1.0.0-win-x64.zip -R simplenty/keepassity
   ```

2. **Install or unpack.**
   - Installer: run `keepassity-1.0.0-win-x64-setup.exe`. It is per-user (no UAC), installs to
     `%LOCALAPPDATA%\Programs\keepassity` with Start menu / desktop shortcuts and an
     uninstaller, and registers a per-user candidate `.kdbx` association without changing the
     Windows default app.
   - Portable: extract `keepassity-1.0.0-win-x64.zip` anywhere and run
     `Run keepassity.cmd` (or `Keepassity.exe` directly). The executable name is
     historical; this is the intended shell.

3. **First run.** Choose an existing `.kdbx` file, open one from WebDAV, or create a new
   database, then enter the master password. Settings, the DPAPI-protected WebDAV password,
   sync state and WebDAV working copies live under `%LOCALAPPDATA%\keepassity\`; backups are
   written next to the database in `.keepassity\backups\<database>\`.

**SmartScreen.** The binaries are not code-signed, so Windows may show "Windows protected
your PC" / "Unknown publisher". Verify the SHA-256 checksum first, then choose
**More info -> Run anyway**. If you are not comfortable with that, build from source.

## Scope

v1.0 is a Windows-first, single-database client for KeePass KDBX databases with native
WebDAV sync and built-in TOTP (see **Features** above), shipped as a portable folder and a
per-user Inno Setup installer for Windows 11 x64. The `v1.0.0` tag and release are created
after the 30-day acceptance period passes (see `docs/release.md`).

Not in v1.0: browser extension, auto-type, Windows Hello, attachments/history/recycle-bin
management UI, multi-database, mobile, macOS, Linux (Linux is planned for v1.x).

## Repository layout

| Path | What |
|---|---|
| `crates/core` | Rust core: KDBX parsing/writing, crypto, merge/sync decisions, TOTP (no IO, no network) |
| `crates/ffi` | C ABI + JSON bridge |
| `crates/cli` | CLI harness for CI, interop and acceptance checks (not shipped with the app) |
| `apps/windows` | WinUI 3 shell (`Keepassity.Mock`); talks to the core through the FFI v1 C ABI |
| `tests/fixtures` | Public KDBX test corpus (MIT, from keepass-rs) plus a generated 500-entry synthetic database |
| `tools/interop` | Test-only interop verification harness (KeePassLib + keepassxc-cli) |
| `docs/` | Architecture, compatibility, testing and release notes |

## Build from source

Toolchain: Rust stable, pinned in `rust-toolchain.toml`; for the Windows shell, .NET SDK
8.0 or newer and the Windows App SDK. `global.json` pins SDK 8.0.100 with
`rollForward: latestMajor`, so a newer installed SDK (for example 10.0.402) is used
automatically; CI installs 8.0.x. Inno Setup 6 is needed only to build the installer.

Core and interop checks (no UI needed):

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Windows app (WinUI 3, self-contained portable build):

```powershell
cargo build -p keepassity-ffi --release
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\publish-windows.ps1 -Zip
```

For IDE work, open `apps/windows/Keepassity.sln` in Visual Studio 2026 (or the
`Keepassity.Mock.csproj` directly); `apps/windows/.vsconfig` lists the required IDE
components (Windows App SDK C#, Windows 11 SDK, .NET desktop workload). Build
`keepassity-ffi` in release mode once first, because the app copies the native
`keepassity_ffi.dll` next to its output and cannot open a database without it.
The app is unpackaged but self-contained, so F5 runs it without installing a runtime.

The portable build lands in `dist/keepassity-<version>-win-x64/` (and a `.zip` with `-Zip`).
Run `Keepassity.exe` or the faster `Run keepassity.cmd`. The native
`keepassity_ffi.dll` and the WinUI XAML resources are copied into the publish output by the
app project, and the publish script fails if either is missing. The portable publish does not
build the installer; the release workflow runs `scripts\build-installer.ps1` for that, and
the script can also be run locally after a publish.

## Testing

See `docs/testing.md` for the full layer breakdown and CI jobs. The main entry points:

```powershell
cargo test --workspace                                  # core, CLI and FFI tests
pwsh -File tools/interop/verify.ps1 -FixturesOnly       # third-party interop (keepassxc-cli)
dotnet run --project tests/app-core/Keepassity.Core.Tests -c Release   # shell service layer
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\test.ps1   # local verification
```

The Windows shell has a non-UI self-test (open fixture copy -> list -> TOTP -> save ->
reopen) driven by `scripts/selftest.ps1`; the CI `app` job and the release workflow run it
against the built/published executable. It exits non-zero on failure and never writes
secrets to the report.
